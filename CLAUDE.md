## Current state: empty base
This repo was a boat-racing game. All of it has been removed because Bowling Roll is a new theme. What is left is the base to build on: **the player, the ground, material/texture helpers, physics and the sky**, drawn by a small `main.js`. There is no HUD, no windows, no audio, no networking, no saves and no game rules yet. The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the safe zone (`SPAWN`, `SPAWN_FACING`, `SAFE_ZONE` layout/colours/shops/boards/bases, `RARITIES`, `MUTATIONS`), `AUDIO`, `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> lighting, clouds, safe zone (awaits the font, builds + colliders), player body, audio -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, safe zone triggers/animation, GPU particles, audio, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z), `safeZone`.
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Safe zone** (`safezone/`, reference map + top-down layout in `SAFE_ZONE.md`): the green studded hub, desert to the north (zone 0 of the lane), tan walls, shop row, leaderboards, player bases. `index.js` `buildSafeZone(scene)` builds everything and returns `update(dt, elapsed, playerPos)` (animations + triggers: SAFE ZONE edge, shop pads, collect pads, reward spots, positional one-shots) and `surfaceAt(p)` (footstep surface). `kit.js` = cached materials (`M`, `S` = studded plastic with world-scaled UVs), shared geometry helpers (`box` bottom-anchored, `boxC` centred, `cyl`, `cone`, ...), `bakeInto`, colliders (`solid`, `solidLocal`, `solidRamp`), decals. `text.js` = `SignAtlas` (flat signs painted into shared 2048 atlas pages, baked with their model), `LabelBatch` (all floating labels as GPU billboards, one draw per page, fade past `far`), `DynLabel` (countdowns). Pieces: `ground.js`, `boards.js` (+ Next Update screen), `bases.js` (1-4 floor bases, slots, switchback stairs, your base's signs + house icon), `stalls.js` (Sell, Dragon Spin, Orb Shop, Treadmill Shop, Cash Shop, Base Skins, Fuse Machine, statue, Suggestions, Orb Pack), `fighters.js` (procedural figurines), `tube.js` (tapered tube for the serpent).
- **Z-fighting rule** (safe zone and anything new): no two visible faces are ever coplanar. Trims stick out of what they trim, overlapping tops sit at different heights, decals float >= 2 cm above their surface and use `polygonOffset` (`decalMaterial`, sign pages).
- **Draw calls**: `bake.js` folds every opaque, non-emissive standard material into vertex colours and merges by surface (roughness/metal bucketed), so a set piece is a few meshes; clouds and the spin wheel are baked too. The whole scene is ~110-140 calls per frame on High incl. the shadow + bloom passes.
- **Sky dressing**: `world.js` `createWorld(scene)` adds the (baked) clouds.
- **Lane** (`lane/`, rules + zone table in `LANE.md`): stepping onto the sand turns you into a winged orb (`orb.js`) that rolls at the Speed stat's pace (`LANE.speedCurve`) through 12 zones (`world.js`: the desert + 11 corridors, gate arches, scenery, floating zone signs, culled by distance). Each zone's guardian (`guardian.js`, rigged bandaged giant: sleep/wake/chase/grab/carry/place/rage/hunt) sits in its base (`house.js`); too slow and it catches you, carries you to a slot and you hatch into a fighter (`actor.js`, animated) that must run back to the safe zone. `index.js` is the form state machine (human / orb / caught / hatching / fighter), the held hotbar fighter in front of the avatar and the HUD feed. `player.js` `setMoveProfile` / `setFrozen` / `placePlayer` serve it; `animator.js` has the `carry` arm overlay (`ANIM.carry`).
- **Your base slots** (`base/mybase.js`, `BASE`): hold E (or the prompt) to place the held fighter on an empty slot of your base's ground floor; it earns income/s into its green pad (collected by stepping on it: cash bundles, "+$" pops); E on a filled slot picks it up / swaps; the orange sign upgrades the slot. `bases.js` hands over the slot positions (`mySlots`) instead of painting static pads for your base.
- **HUD** (`hud/hud.js` + `hud.css`): money/Speed counters, Shop/Base/Sell teleports, the right menu grid (`hud.onMenu(id, fn)`, `setAlert`), lane zone bar + luck, speedometer, Run banner / hatch message / vignette, hotbar (keys 1-9, 0; Backpack hooks `setBackpackOpen`, `onHotbarTap`, `hotbarSlotAt`, `hotbarRect`), hold-E prompt. `hud/icon.js` renders hotbar portraits offscreen. `state.js` holds money, speed, hotbar, slots.
- **Windows** (`ui/`, `initUi` in main.js; config `INDEX`, `REBIRTH`, `BOOSTS`, `PLAYTIME`, `DAILY`, `QUESTS`, `GAME_SETTINGS`, `MUTATIONS` incl. `id`/`multi`/`weight`): `shell.js` window layer (one open at a time, Esc / tap outside closes, swallows game keys), `playtime.js` (HUD Rewards button), `indexwin.js` (162-fighter roster x 11 mutation tabs, silhouettes until discovered, 20 of a mutation unlocks its base skin -> `state.indexClaimed`), `rebirth.js` (cash + Speed bars, Rebirth resets both, Skip! costs $), `quests.js`, `daily.js` (calendar corner button), `settings.js` (gear: Low Gfx -> Low preset, Disable VFX -> particle density 0, Mute Music -> `A.amb` bus, Overhead names -> camera layer `OVERHEAD_LAYER` = 3 that `text.js` puts DynLabel sprites + the `overhead` LabelBatch on), the x2 Speed button (left edge, bought with $) and the x2 Luck badge. `portrait.js` renders fighter portraits / silhouettes offscreen, 2 per frame. `server.js` attaches to net.js's room for the server-clock systems (`playtime`, `quests`, `daily` + `*Result`, `uiSync`) and runs the same rules on the page clock when offline. `roster.js` = the fixed roster (`rosterFor`, `rollMutation`, `indexKey`, `makeFighter`); `state.js` adds `rebirths`, `playtime`, `discovered`, `indexClaimed`, boosts, `settings`, `moneyMulti()`, `effectiveSpeed()`, `luckMulti()`, `recordHatch(f)` / `recordSell(n)` (feed Index + Daily Quests). Nothing is sold for premium currency.
- **One-shot effects**: `fx.js` pooled CPU particles (puffs, dust, hatch vortex, flashes, trails) + instanced confetti, one draw call per pool.
- **Particles**: `particles.js` GPU emitters (closed-form motion in the vertex shader, one draw each; density follows the preset via `setParticleDensity`).
- **Audio** (`audio/`): `core.js` one AudioContext on the first gesture, buses -> glue compressor -> limiter, one-shot voice budget; `synth.js` physical building blocks; `sfx.js` safe zone one-shots (steps per surface, jump/land, zone enter/leave chimes, pad ding, coins, wheel ticks, steam, sparkle), each throttled per name with random variation; `ambience.js` breeze + Fuse Machine hum (built once, only smoothed level/pan ramps); `index.js` `installAudio`, `updateAudio(dt, state)`, `spatial(x, z, near)`.
- **Notices**: `toast.js` + `toast.css` one-line notices top-centre (clear of the Bloxity toolbar).
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; unused so far).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
